# Projects, Behavior Systems, Areas of Focus and Objectives

## Project statuses

| Status | Means | Notes |
|---|---|---|
| `Planning` | committed, not yet clarified or designed enough for normal execution | may have executable planning Tasks; a full plan is not required to move to `Active` |
| `Active` | part of the current portfolio and able to progress through Tasks | stays `Active` even when all its Tasks are `Waiting For` or `Scheduled` |
| `Paused` | still a valid commitment, progress deliberately suspended | its Tasks keep their statuses and stay out of Available Now (the short list of Tasks to start now); its time-fixed commitments (`ontology.md`) still count: ask the person what to do with each; on resuming it returns to `Active` |
| `Done` | the Definition of Done is satisfied | final; stays `Done` even if its Key Result did not improve |
| `Canceled` | closed without satisfying the Definition of Done | final; not a judgement of failure |

When a Project becomes `Done` or `Canceled`, settle each of its unfinished Tasks with the person: `Done`, `Canceled`, or detached or moved to another Project. `Failed` only if they say the commitment stood and did not happen.

## Behavior System

- Lifecycle: `Designed` (formulated, not installed), `Installing` (being introduced), `Stabilizing` (repeating, structure still needs correction), `Maintenance` (stable, periodic control), `Retired` (no longer needed or replaced). Choose the one that matches how far it is installed.
- A system with no repetition Tasks looks the same as an abandoned one and proves nothing about automaticity.
- When it is not working, name a design lever (cue, context, friction, minimum or target version, environment, success rule, recovery rule), not "indiscipline".

## Area of Focus and Objective

- The `Mode` of an Area of Focus: `Advance` invests extra resources and allows significant change; `Maintain` keeps an acceptable state without expansion; `Minimum` temporarily protects only the critical minimum. It is a choice, not a grade: do not suggest raising it just to balance time between Areas of Focus. Changing a `Mode` or a `Standard` on your own recommendation is a decision for the person.
- Link a Project or Behavior System to a Key Result, not directly to an Objective; reach an Objective's Projects and Behavior Systems through its Key Results. An Objective needs at least one Key Result, each one evidence, not work.
- A review of an Objective ends in one of `Continue`, `Adapt`, `Pause`, `Abandon`, `Achieved`. `Continue` changes nothing and needs no decision: state it. The other four need the person's decision.

## Links and hierarchy

- Link upward only where the link changes a decision. For a large Project, raise which Area of Focus it supports, which Key Result should move, whether it fits current capacity and what gives way once it is `Active`.
- Do not require every object to link to every level: no Objective for ordinary maintenance, no Project for every Task. A Behavior System may support a Key Result, an Area of Focus or a Project.
- Do not create an object or ask for a confirmation that would change no decision.
