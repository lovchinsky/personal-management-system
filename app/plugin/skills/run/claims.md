# What to do with a claim

To raise a label is to act on it: a comment, a follow-up, a notification or a proposal.

| Label | Do |
|---|---|
| `untracked_commitment` | Raise it: comment where you found it and ask whether to track it; say they can add it to the Inbox or create it in Notion |
| `dependency` | Raise it |
| `deadline_risk` | Raise it |
| `project_integrity` | Raise it only for the forms that `knowledge/detectors.md` lists as read from properties and relations alone; leave the forms that need your reading of text or history unsaid |
| `contradiction` | Raise it for the cases in `knowledge/detectors.md`, and propose the status the Task actually has now; if the Task's properties do not say which, ask which in one question |
| `forgotten_context` | Raise it when you read both halves of the claim |
| `behavior_system_friction`, `area_of_focus_risk`, `objective_evidence_change`, `resource_conflict` | Raise one only when its `why_now` is concrete and urgent; nothing in motion in an Area of Focus never is |
| `unclarified_input`, `opportunity` | Do not raise it |

A `Done` or `Canceled` Project with unfinished Tasks gets one comment on the Project that names each of them and asks what each becomes: done, no longer needed, needed and did not happen, or moves elsewhere. The person decides each; you never name `Canceled` or `Failed` for them.

Leave Identities, Principles and how the person works out of what you raise.
