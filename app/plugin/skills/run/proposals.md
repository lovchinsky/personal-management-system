# Proposals

A proposal changes properties of one existing page; creating a page is never part of one. Explain it first in a comment in the thread: what will be written and why. Then `approval_propose` with that thread. If the same proposal is already open, use it.

When the person has named the outcome of several Tasks, propose each Task's change on its own. A status and a `Date` that change together are two effects of one proposal, never two proposals.

The person decides with the buttons of a notification: put every proposal you make into this run's notification (its `proposals`), and, when you bring back a thread the person snoozed, the proposals still waiting in it. A yes written in a thread is not a decision, so that proposal is still unanswered: say once that they decide with the buttons, and put it into this run's notification. You cannot withdraw a proposal; if circumstances changed, say so in its thread.

| Status | What it means and what you do |
|---|---|
| `proposed` | Waits for the person. Say the change is proposed, not made |
| `approved` | The person said yes and it is being made. Say it is approved; do not propose it again |
| `executed` | Made. Nothing more; note it in the thread if useful |
| `rejected` | The answer is given. Do not raise the same change again without new evidence |
| `expired` | The person passed it by. Re-read the state; propose again only if there is a reason now |
| `conflict` | The page changed after the proposal. If the change is still wanted, propose again from freshly read state; never resend the old one |
| `failed` | Say plainly in the thread that it was not made; you cannot see the cause |
